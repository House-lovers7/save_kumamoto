- 全14カード期限切れ時の鮮度シグナルと「まずやること」の残存

**未検証 — エミュレータでは代替できないもの。**

- **実機（physical device）**: 実タッチ、実ディスプレイのコントラスト、低速回線、実機のTalkBack/VoiceOverジェスチャ。
- **TalkBackの実発話**: TalkBackの起動とアプリウィンドウへのアクセシビリティフォーカスまでは確認したが、読み上げ文字列を取得する手段がないため、読み上げ順・重複の有無は確認できていない。

- **署名・審査**: Apple/Googleの署名済みストア成果物と審査。
- **誤案内を止める経路**: `expo-updates` を導入しておらず、`app.json` に `updates` / `runtimeVersion` の設定もない。カードデータはアプリに同梱され、起動時に何も取りに行かない（通信ゼロ設計）。誤りが見つかっても、**ストア審査を通した新バージョンを配布するまで（数日〜）止められない**。Webは環境変数で数分以内に止まるので、この非対称を運営者が受諾するまで申請しない（上記「公開停止条件」#7）。

## 公開の継続条件

ブロッカーではなく、公開後もずっと続く前提。

- 24時間期限のため、**毎日1回の再確認巡回が必須**。巡回が止まれば全カードが期限切れに戻る。古い静的時刻のまま公開しない。氷川町の配布カードは当日限りの告知なので、共通の24時間ではなく配布終了時刻で失効させている。
- **巡回の判定ルールは2段階で厳しくしてある**（「リンクが生きているか」→「そのページにカードの話題があるか」→「カードの手順が1つずつリンク先で実行できるか」）。経緯は `docs/FIXES.md`「出典側の到達性」、手順は `docs/OPERATIONS.md` 第5章。
- **2026年8月1日13時から、出典の核心情報をカード内に出している**（`facts`）。**これは巡回の作業を増やす。** 写した行はすべて劣化するため、毎日の巡回で出典と1行ずつ照合する。その日限りの内容（`dated`）は期限切れで自動的に消えるが、これは「昨日の給水所へ人を向かわせない」ための安全弁であって更新の代わりではない。
- 巡回を続けられなくなったときの手順は `docs/OPERATIONS.md` 第5章「巡回を続けられなくなったとき」。巡回が止まっても、全カードは端末時計による失効表示で自動的に「現在の状況は確認できません」へ縮退する（アプリが古い情報を新しいものとして出し続けることはない）。

## Web公開のブロッカーから外したもの（2026-08-01 スコープ改訂）

### 1. 熊本市の3カード（食料・生活用品／トイレ／乳幼児）の公式案内欠落

従来は「被災者が最も困る領域が3つ空いた状態では一般公開しない」としていた。改訂後は、実装済みの正直表示（`sourceStatus: "unavailable"`、「公式の案内を確認できていません」＋何が確認できていないか＋問い合わせ先）のまま公開する。

- **経緯**: 2026-08-01 09:30 JST の巡回時点で熊本市の3カードの公式案内を確認できていない。**氷川町では食料配布が公式に出ていた**（「8月1日（土曜日）の水・食料品の配布について」、時間と場所つき）ためカードを追加した（`food-hikawa`）。**熊本市には無い**ことは、被災者支援制度の冊子PDFの目次まで当たって確認している（生活必需品の支給は申請受付前で、支給品一覧も前回災害時の内容と明記されている）。
- **外した理由**: 探索導線は枯渇するまで再探索済みで（`docs/OPERATIONS.md` 第5章、同じ導線の再探索は禁止）、これ以上は開発・運用側の作業では埋まらず、公式が案内を出すのを待つしかない。「未確認」を隠さず明示することは、本アプリが唯一守ると約束した品質基準（鮮度と失効を正直に出す）の適用であって違反ではない。確認済みカード（給水12か所・入浴12か所・り災証明ほか）を届けないことの不利益が上回ると判断した。
- **残リスク**: 熊本市域の利用者は3領域で「確認できていません＋問い合わせ先」しか得られない。巡回で公式案内を発見し次第カード化する。

### 2. 現地評価（熊本在住者または現地支援者3〜5人）→ 公開後の改善入力へ

- 実機・主要シナリオの現地評価は未実施のまま公開する。
- **外した理由**: 評価者の募集と実施に日数がかかり、その間、確認済みの情報が届かない。実ブラウザQA（コントラスト・タップ領域・オフライン・特大文字・キーボード）とエミュレータ実測は済んでいる。
- **残リスク**: 実利用文脈（実機の低速回線、高齢者、支援技術の実発話）の問題は公開後に発見される。発見窓口は GitHub Issues。

## リリース手順

### R1（Web公開）

1. `lib/disaster-data.ts` の公式情報と全時刻を更新し、`npm run gen:mobile-data` を実行する。
2. `npm run lint && npm test && npm audit` を実行する。
3. remote を設定し、問い合わせ窓口（GitHub Issues）の URL を確定する（外部送信のため承認後）。
4. 明示承認後にWebを本番公開する。`vinext build --prerender-all` は使わない（`/` が静的化されると停止スイッチが効かなくなる）。
5. **本番URLで停止スイッチを実操作する。** secretを設定して別端末で `/` と `/status` の切り替わりを確認し、反映までの実時間を記録する。停止中に無害な変更をデプロイしても停止が維持されることも確認してから解除する（上記「公開停止条件」#3 の5手順）。
6. 本番URLを別端末・低速回線・オフライン再起動で確認する（公開告知はこの後）。
7. 公開URLと検証結果を、承認された送信アカウントから指定先へメールする。

## Rollback

- Web：直前の検証済みversionへ戻す。重大な誤案内時は `npx wrangler secret put EMERGENCY_MODE`（値 `true`）で
  緊急縮退モードを有効にする。**再ビルド・再デプロイは不要**。`/status` で状態を確認する。
  plain text var は `wrangler deploy` が既定でvarsを全消しするため次のデプロイで消える。secretを使う。
- iOS/Android：審査提出を停止し、配布中buildの段階的公開を停止する。必要に応じて修正版のversion/build番号を更新する。
  **配布済みのアプリに対しては停止手段がない**（`expo-updates` 未導入、通信ゼロ設計）。
- 情報：期限切れカードは削除せず「現在の状況は確認できません」と表示し、公式サイトへの導線だけを残す。

## 停止の到達範囲

緊急縮退モードを立てても、全利用者へ即座に届くわけではない。

| 対象 | 届くか | 遅延 |
|---|---|---|
| オンライン利用者の次のページ遷移・再読込 | 届く | 次のナビゲーションまで（`public/sw.js` はnavigationをnetwork-firstで取得） |
| 開きっぱなしのタブ | 届かない | 利用者が再読込するまで（ポーリング未実装） |
| オフラインのPWA利用者 | 届かない | 再接続してナビゲーションするまで |
| iOS / Androidネイティブ | 一切届かない | ストア審査を通した新バージョンの配布まで（数日〜） |

`isExpired` による失効表示は端末の時計で動くため、停止が届かない利用者に対する唯一の自動的な劣化通知になる。
**停止スイッチ（サーバー側の判定）と失効表示（端末側の判定）は別物**として扱う。
詳細と運用手順は `docs/OPERATIONS.md`、実測証拠は `docs/qa/emergency-mode-2026-07-31/`。
