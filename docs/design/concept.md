## 一文で言うと

被災者が「いま何に困っているか」から、公式な災害・生活支援情報へ短時間で到達するための**読み取り専用**の道案内アプリです（`README.md` 冒頭, `docs/DESIGN.md:23`）。

## 解こうとしている問題

災害時は情報が無いのではなく、**どれが今も有効か分からない**ことが問題になります。検索結果は前回の災害のものかもしれず、SNSの「配ってました」は数時間前の情報かもしれません。利用者は情報の鮮度を確かめる手段を持たないまま、給水に向かい、店へ行き、申請の期限を逃します（`docs/DESIGN.md:25-29`）。

## ターゲット

- 熊本県内の被災者（対象自治体: 熊本県全域・熊本市・宇城市・宇土市・八代市・氷川町・その他の市町村。`lib/disaster-data.ts:96-104`）
- 令和8年熊本地震の被災者支援を主眼にした構成（カードの `summary` に地震名の言及あり。`lib/disaster-data.ts:169` の `kumamoto-city-hub` カード）
- Web（PWA）が主導線。R1（現行公開スコープ）はWebのみで、iOS/AndroidネイティブはR2へ延期（`README.md`「これは何か」）

## このアプリが引き受ける範囲／引き受けない範囲

```text
引き受ける : 困りごと → 該当する公式ページ → そこで何を確認すべきか
引き受けない: 現在の稼働状況の判定（給水車が今いるか、店が開いているか、道が通れるか）
```

現在の稼働状況は、自治体・現場からの更新経路が無ければ原理的に出せません。**無い情報を「たぶん大丈夫」で埋めない**ことを、機能の多さより優先します（`docs/DESIGN.md:31-39`）。

地域ごとの一覧（`area-map`）もこの線を越えません。タイルが出しているのは「公式ページで確認できた案内が何件あるか」というカバレッジであって、その地域が今どうなっているかではありません。件数だけを地図状に並べると「多い＝安全」と読まれるため、何を数えているのかの注記を画面から省略できない形で置いています。点（ピン）を置かないのも同じ理由で、ピンは「そこが今使える」と読ませるうえ、施設名から座標を引くこと自体が推測の混入にあたります（`docs/adr/0002-area-map-uses-municipality-tiles-not-pins.md`）。

## 唯一守ると約束した品質基準

**鮮度と失効を正直に出す。** これを崩す変更は、他のどんな利点があっても入れません（`docs/DESIGN.md:43`）。具体的には次の3つです。

1. **期限切れは期限切れと出す。** 全カードに `expiresAt` があり、過ぎたカードは「現在の状況は確認できません」に切り替わります。基本手順は残しますが、場所・時間は出しません（`lib/disaster-data.ts:1065-1067` `isExpired()`）。
2. **公式ページを再確認せずに期限を延ばさない。** 鮮度の捏造にあたるため禁止（運用手順は `docs/OPERATIONS.md`）。
3. **確認できていないことを、確認できたように見せない。** リンクは生きているのにカードの話題が無いときは `sourceStatus: "unavailable"` とし、何が確認できていないのかを本文として出します（`app/home-client.tsx:444-449`）。

## 提供価値（実装済みの誤認防止表示）

被災者が最も損をするのは、情報が無いことより**取り違え**です。実装済みの表示は3種類（`lib/disaster-data.ts:33-92` の `ActionCard` 型）。

なお `docs/DESIGN.md:61-70`（2026-07-31時点）は「実装済みのものは2種類」として `verifyPoints` / `irreversibleOrder` だけを挙げていますが、`facts` も実装済みです（`lib/disaster-data.ts:1040` `FACT_INLINE_LIMIT`、`1077-1080` `visibleFacts()`）。現行コードを優先して3種類とします。

| 表示 | 目的 | 例 |
|---|---|---|
| `facts` | 出典ページの核心情報（住所・時間・電話番号等）をカード内に写し、リンク先を探索させない | 応急給水所12か所の学校名・住所（`water-station` カード） |
| `verifyPoints` | 混同すると健康被害・無駄足になる区別を、選択肢と理由で強制表示する | 給水の「飲料用 / 生活用水」（水質検査10項目が根拠） |
| `irreversibleOrder` | 順序を誤ると取り返しがつかない手続きを出す | 「片付けや修理の前に写真を撮る」「支払い・契約の前に相談する」 |

いずれも**出典ページに実際に書かれている記載だけ**を根拠にします。区分を推測で作りません。

## 設計原則（しないこと）

ログイン / GPS / 住所 / 氏名 / 被害写真 / 健康情報 / 利用者投稿 / 広告 / アクセス解析を**一切扱いません**。収集しないのではなく、**収集する経路をコードに持ちません**（`docs/DESIGN.md:54-59`, `app/status/page.tsx:22-26`）。そのため、このアプリには利用者を識別する手段が無く、サーバーに保存される利用者データもありません。

R1で実装しない機能は `README.md`「これは何か」に要約されています（ログイン・GPS・利用者投稿・DM・支援要請・医療判断・寄付決済・広告・アクセス解析等）。

## 公開スコープ（R1 = Web先行）

2026-08-01 決定で、R1公開はWeb（PWA）のみに再スコープされました。iOS/Androidネイティブはコードとエミュレータ検証を保持したままR2へ延期しています。理由は、実機検証・ストア審査・誤案内を止める経路（`expo-updates`）という重い境界がネイティブ側だけに残っており、Webの公開をそこへ連結すると公開できる状態のWebまで止まるためです（`README.md`「公開状態と残課題」）。公開前に残る課題（No-Go）の全体と判定は `docs/RELEASE_AUDIT.md` を参照してください。
