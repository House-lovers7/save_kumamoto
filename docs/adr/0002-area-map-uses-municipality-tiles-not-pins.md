# ADR-0002: 地域マップは点（ピン）を置かず、市町村の面で塗る

- 日付: 2026-08-02
- 状態: 承認済み（運営者が本日承認）
- 関連: `docs/design/concept.md`、`docs/design/api.md:45`、`lib/disaster-data.ts`（`areaCoverage()`）、`docs/design/screens.md`

## 文脈

「どの地域がどういう状況か」を見て分かる形にしたい、という要望が出た（2026-08-02）。参照元として `worldmonitor`（同ワークスペース内の別プロジェクト）のコンセプトを使いたい、という指定があった。

`worldmonitor` を調査した結果、可視化の実装（MapLibre GL JS + deck.gl の3Dグローブ、Vercel Edge Functions と Railway Relay 経由の実行時データ取得）は本アプリへ持ち込めない。実行時に外部を叩き続ける構成であり、「実行時に外部へ出ていく通信は無い」（`docs/design/api.md:45`）と正面から衝突する。

一方で借りる価値があるコンセプトは可視化ではなく **Intelligence Gaps**（28以上のデータソースを `fresh / stale / very_stale / no_data / error` に分類し、**データが取れていないことを画面に出す**）だった。「見えない＝無事」と誤読させないための設計であり、本アプリが既に持っている `sourceStatus: "unavailable"` と `isExpired()` と同じ思想である。

本アプリ側の制約は次のとおり（2026-08-02 実測）。

| 事実 | 根拠 |
|---|---|
| `ActionCard` 型に緯度経度フィールドが無い | `lib/disaster-data.ts` の `ActionCard` 型 |
| 構造化された場所は `areas`（7値の市町村列挙）だけ | 同型の `areas` フィールドと `municipalities` |
| 施設名・住所は `facts.items` の自由文字列（「南区 隈庄小学校（南区城南町隈庄270）」） | 同型の `facts` フィールド |
| 地図系ライブラリは Web・ネイティブとも存在しない | `package.json` / `apps/mobile/package.json` |
| `Permissions-Policy: geolocation=()` で位置情報APIを無効化済み | `worker/index.ts` の `applySecurityHeaders()` |

## 決定

地域マップを **点（ピン）ではなく面（市町村）で塗る図** として実装する。

- 描画は自前の CSS Grid と文字のみ。地図ライブラリ・タイル画像・SVGのパス座標・行政区域データのいずれも持たない
- 実際の地理に沿った外形を持たない模式配置とし、「位置関係は実際の地理と異なります」を画面に出す
- 各タイルが出すのは `areaCoverage()` が数えた **公式ページで確認できた案内の枚数**（および期限切れ・未確認の内訳）であって、現地の稼働状況ではない。「件数は公式ページで確認できた案内の数です。現地が今使えるかどうかではありません」を画面に出す
- 数えるのは **その市町村を名指ししたカードだけ**。県全域カードは各市町村へ足し込まず、図の下に1度だけ別枠で出す
- 既存の市町村 `<select>` を置き換える（操作子を純増させない）
- 緊急縮退モードでは図ごと消す

## 却下した案

### ピン（点）を置く地図

`facts.items` の施設名（「隈庄小学校」等）から緯度経度を引く必要がある。出典に座標は書かれていないので、これはジオコーディングによる**推測の混入**であり、「入れてよいのは出典に書かれている記載だけで、住所・時間・電話番号を推測で作らない」（`lib/disaster-data.ts` の `facts` フィールドの規約）に反する。

加えて、地図上のピンは「そこが今使える」と読ませる。本アプリは「現在の稼働状況の判定（給水車が今いるか、店が開いているか、道が通れるか）」を引き受けないと決めている（`docs/design/concept.md`）。ピンは、その判定を表示形式だけで肩代わりしてしまう。

### 外部のタイルサーバからベースマップを読む

タイル配信は実行時の外部通信そのもので、利用者のIPが第三者へ渡る。「アプリのサーバー（Worker）が公式サイトを取りに行くことはない」「利用者を識別する手段が無く、サーバーに保存される利用者データもありません」の2つを同時に崩す。

### 行政区域データから実形状のポリゴンを同梱する

実行時の外部通信はビルド時取り込みで回避できるので、この案だけは技術的には成立する。却下したのは費用対効果による。

- 外部データのライセンス確認と出典管理が新たに増える。本アプリの出典管理は `ALLOWED_SOURCE_HOSTS`（7ドメイン）を機械で強制する形で成立しており、性質の違う「地理データの出典」をもう1系統持つと、巡回のたびに照合する対象が増える
- 得られるのは地図らしい見た目だけで、伝えたい情報（どの地域に何件の確認済み案内があるか）は面を塗る方式と変わらない
- 「熊本県全域」と「その他の市町村」はポリゴンとして存在しない。実形状にすると、この2つだけ表現できずに図から落ちる

将来、実形状が必要になった場合は本ADRを更新して再検討する。その際も実行時の外部通信ゼロは維持する。

### 地図をやらず、非地理の欠損一覧だけにする

Intelligence Gaps の思想は満たすが、「どの地域がどうか」を一覧する要望に応えない。面で塗る方式が同じ制約を守ったまま要望を満たせるため、こちらを採らなかった。

## 根拠

守ると約束したもの（GPSを収集しない・稼働状況を判定しない・推測で座標を作らない・実行時の外部通信ゼロ）を1つも崩さずに、`areas` という**既に持っているデータ**だけで描ける。何も推測しない。

そのうえで、この図の本体は件数を見せることではなく、**固有の案内が0件の地域を0件のまま見せること**にある。2026-08-02 時点では宇土市がそれにあたる。従来の `<select>` では、宇土市を選んで県全域の案内が並ぶため、その地域の情報を持っていないことが利用者に伝わらなかった。

## 影響

- `lib/disaster-data.ts` の末尾に `areaCoverage()` を追加した。末尾へ置いたのは `docs` の行番号参照をずらさないためで、`scripts/generate-mobile-data.mjs` の tail 切り出しがマーカーからEOFまでを取るので、ネイティブ側へも複製される
- 数え方と注記は `tests/data-contract.test.mjs` / `tests/rendered-html.test.mjs` / `tests/emergency-mode.test.mjs` / `tests/mobile-parity.test.mjs` が機械で固定している
- 依存追加・外部URL追加・位置情報APIの使用はいずれも0件。CSP と `Permissions-Policy` は変更していない
