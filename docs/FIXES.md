# 修正した不具合の記録

実装・QA の過程で見つけて直した不具合を、発見経路ごとに記録する。

このファイルは **README とは粒度が違う**ため分けている。README は「何のアプリで、どう動かし、どんな画面があるか」を書く場所で、個々の不具合の症状・原因・対処はここに集める。公開可否の判定は `docs/RELEASE_AUDIT.md`、運用時の訂正・停止手順は `docs/OPERATIONS.md`。

書式は **症状 → 原因 → 対処** で揃える。原因が「なぜそう書いてしまったか」まで分かっているものは、同じ間違いを繰り返さないために残している。

## 緊急停止スイッチ（2026年7月31日）

このアプリで最も危険な不具合が出た領域。誤案内を止められることが公開の前提になっているため、ここが壊れていると他がすべて正しくても公開できない。

### 止めたつもりで止まっていなかった

- **症状**: 運営者が停止操作をすると `/status` は「緊急縮退中」と表示するのに、利用者が見る `/` にはカードが出続けていた。SSR の初期HTMLだけが縮退表示になり、hydration 後にカードが復活していた。
- **原因**: 停止フラグをクライアントコンポーネント内の `process.env` で読んでいた。クライアントバンドルでは `process.env` が空オブジェクトへ置換されるため、常に `false` になる。Server Component である `/status` だけが正しく読めていたので、**運営者は止めたつもりで、利用者には案内が出続ける**という最悪の食い違いが起きていた。
- **対処**: サーバー側で読んで props で渡す形に変更した（`lib/emergency-mode.ts` / `app/page.tsx` → `app/home-client.tsx`）。読み取り経路は `tests/emergency-mode.test.mjs` がソースコードの形そのものを検査して固定している。

### `NEXT_PUBLIC_EMERGENCY_MODE` は効かないのではなく有害だった

- **症状**: README が案内していた `NEXT_PUBLIC_EMERGENCY_MODE=true npm run build` を使うと、以後どの環境変数を変えても停止できなくなる。
- **原因**: vinext はビルドプロセスの `NEXT_PUBLIC_*` を rsc / ssr を含む全環境へ define する。`false` を付けてビルドするとサーバー側にも定数として焼き付く。
- **対処**: この手順を README から削除し、`NEXT_PUBLIC_` を付けてはいけない理由をコード（`lib/emergency-mode.ts`）のコメントと README の両方へ書いた。`tests/emergency-mode.test.mjs` が `NEXT_PUBLIC_[A-Z]` の出現を検査して再発を止める。

### 縮退中に、押しても何も起きない操作子が残っていた

- **症状**: 緊急縮退中に困りごとグリッド・市町村/検索・スキップリンクが残っていたが、押しても何も起きなかった。
- **原因**: 行き先である `#actions` セクションだけを消していたため、そこへ誘導する操作子が宙に浮いた。
- **対処**: 災害時に無反応のボタンを残さないよう、操作子ごと描画を外した（`app/home-client.tsx` の `{!emergencyMode && ...}`）。

**実測証拠**: `docs/qa/emergency-mode-2026-07-31/`。同一ビルドのまま環境変数だけで `/` と `/status` が切り替わること、RSCペイロードに判定が載ること、実ブラウザの hydration 後のDOMでカードが復活しないこと（対照の通常表示では14カードを検出）、workerd（本番と同じランタイム）で `.dev.vars` から届くこと、クライアントバンドルに変数が混入しないことを確認。hydration警告・コンソールエラーは0件。

## 出典側の到達性（2026年8月1日）

- **症状**: カードのリンクを開いても、目的の情報にたどり着けないケースがあった。り災証明の窓口は開いた位置から2.2画面ぶん下、災害廃棄物の問い合わせ先は2.1画面ぶん下にあった。旧 `support-systems` の出典（集約ページ）に至っては、一覧が JS のページ送りのため**開いた最初の状態では目的の記事名が DOM に存在せず到達できなかった**。
- **原因**: 「リンクが生きているか」だけを巡回の判定基準にしていたため、リンク先での到達コストを見ていなかった。
- **対処**: 出典の核心情報（給水所12か所の学校名と住所、入浴施設12か所、各窓口の電話番号など）をカード内に写す `facts` を導入した。あわせて巡回の判定を「リンクが生きているか」→「そのページにカードの話題があるか」→「**カードの手順が1つずつリンク先で実行できるか**」へ2段階で厳しくした（`docs/OPERATIONS.md` 第5章）。
- **副作用として増えた運用負荷**: 写した行はすべて劣化するため、毎日の巡回で出典と1行ずつ照合する必要がある。その日限りの内容（`dated`）は期限切れで自動的に消えるが、これは「昨日の給水所へ人を向かわせない」ための安全弁であって更新の代わりではない。
- **実測証拠**: `docs/qa/link-depth-2026-08-01/`

この基準変更により、8月1日に `evidence` カードの「建物の外側4方向を撮影する」が出典のどこにも書かれていないことが判明し、出典の記載へ書き直した。7月31日の `shelter` と同種の、`unavailable` 表示より危険な誤認だった。

## 写した住所が出典と1文字違っていた（2026年8月4日）

- **症状**: 無料入浴の `bath-kumamoto` カードで、大福湯の所在地を「中央区坪井2丁目**5-8**」と出していた。出典（`kiji00372200`）の記載は「中央区坪井2丁目**5-28**」。
- **原因**: 特定できていない。8月1日に12施設を `facts` へ写した時点の書き写し誤りか、出典側がその後に訂正したかのどちらかで、**8月1日時点の出典本文が手元に残っていないため確定できない**。機械照合（`npm run patrol:diff`）は住所を独立した語として突き合わせるので、この1文字違いは 8月4日の巡回で `fact missing` として検出できた。
- **対処**: 出典の記載（5-28）へ直した。
- **残る疑い**: 書き写し誤りだった場合、**他の `facts` にも同種の誤りがある可能性がある**。ただし 8月4日の巡回では 20カード・全項目が出典と一致（`patrol:diff` exit 0）しているため、現時点で検出できる不一致は残っていない。写した行が増えるほどこの種の劣化は起きるので、巡回の機械照合を省略しないこと。

## ネイティブ（React Native / Expo、2026年7月31日）

### Web のロジック移植時に持ち込んだもの

| 症状 | 原因 | 対処 |
|---|---|---|
| 鮮度シグナルが全件期限切れでも緑＋固定時刻のままだった | 起動時刻を定数で保持していた | 実データ連動へ変更 |
| 期限切れカードに行動手順が出なかった | 期限切れ時に本文ごと隠していた | 手順は残し、場所・時間だけ隠す方式へ統一 |
| 開いたままだと失効判定が更新されなかった | 起動時刻を定数で保持していた（同上） | 現在時刻を定期更新する方式へ |

あわせて、カードデータを Web の `lib/disaster-data.ts` から生成する方式へ変更し、二重管理をやめた（`npm run gen:mobile-data`）。

### Androidエミュレータの実描画で見つけたもの

Pixel 8 / API 35、`npx expo run:android` のローカル開発ビルド（Expo Go は使わない）で検出。**静的レンダリングでは出なかった**類の不具合が中心。

- **システムのBACKボタンで、オフライン行動カード・安全と出典の各画面からアプリごと終了していた。**
  `predictiveBackGestureEnabled: true` が `android:enableOnBackInvokedCallback="true"` を生成し、Androidの仕様上 `KEYCODE_BACK` による傍受が無効になっていたため。ヘッダーの戻る矢印は正常だったので、**経路によって挙動が割れていた**。予測型バックジェスチャは既定（無効）へ戻した。
- **文字「特大」でカード見出しの行が重なっていた。**
  `fontSize` だけを倍率で拡大し `lineHeight` を固定値のままにしていたため、行間比が1.00になっていた。行間を倍率へ追従させた。
- **文字サイズ設定がオフライン行動カード・安全と出典の画面に効かず、標準サイズで描画されていた。**
  通信が切れたとき一番読む必要のある手順が読めない状態だったため、設定を3画面で共有するようにした（`apps/mobile/src/use-text-scale.ts`）。
- **119/110、「期限切れ」タグ、件数、「公式サービスではありません」の断り書きが文字サイズ設定に追従していなかった。**
  安全上重要な文字を小さいまま残さないようにした。

**タップ領域**: 修正前は44dp未満10件・48dp未満15件だったものを0件へ（`apps/mobile/scripts/qa/tap_targets.py`）。uiautomator の bounds は画面外をクリップするため、対象を画面内に入れてから測る必要がある。

**実測証拠**: `docs/qa/android-2026-07-31/`
