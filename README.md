# くまもと いまどうするナビ

熊本の被災者が「いま何に困っているか」から、公式な災害・生活支援情報へ短時間で到達するための**読み取り専用**アプリです。

> このプロジェクトは熊本県、熊本市、NERVその他の公的・民間サービスの公式アプリではありません。自治体、消防、警察、医療機関等の指示を優先してください。

| | 状態 |
|---|---|
| Web（PWA / vinext + React） | **R1で公開**（現行スコープ） |
| iOS・Android（Expo / React Native） | R2へ延期（コードとエミュレータ検証は保持） |

## これは何か

災害時は情報が無いことより、**どれが今も有効か分からない**ことが問題になります。このアプリは困りごとから公式ページへ案内し、その情報が**いつ確認されたもので、いつ失効するか**を必ず一緒に出します。

**引き受ける**: 困りごと → 該当する公式ページ → そこで何を確認すべきか
**引き受けない**: 現在の稼働状況の判定（給水車が今いるか、店が開いているか、道が通れるか）

守ると約束した唯一の品質基準は **「鮮度と失効を正直に出す」**。期限切れは「現在の状況は確認できません」へ切り替え、公式ページを再確認せずに期限を延ばしません。

ログイン / GPS / 住所 / 氏名 / 被害写真 / 健康情報 / 利用者投稿 / 広告 / アクセス解析は**一切扱いません**。収集しないのではなく、**収集する経路をコードに持ちません**。そのため利用者を識別する手段が無く、サーバーに保存される利用者データもありません。

設計の背景と判断理由は **[docs/design/concept.md](docs/design/concept.md)**。

## 5分で動かす

**必要環境**: Node.js 22.13以上 / npm（iOS・Androidのローカル起動には Xcode または Android Studio）

```bash
npm install
npm run dev              # ポート指定は npm run dev -- --port 3002
```

検証（変更したら必ず通す）:

```bash
npm run lint             # tsc --noEmit
npm test                 # 本番ビルド + node --test（60件・2026-08-02 実測）
npm audit
```

本番と同じランタイム（workerd）で確認する場合:

```bash
npm run build && npm run start
```

モバイル:

```bash
cd apps/mobile
npm install && npm run start     # npm run ios / npm run android
npm run typecheck && npm run lint && npm run export:all
```

`export:all` は iOS と Android の JavaScript/Hermes bundle を生成します。署名済み `.ipa`/`.aab` は生成しません。ストア用ビルド（`npx eas-cli build`）は外部通信・課金・資格情報を伴うため、実行前に承認が必要です。

## 画面と操作

| 経路 | 画面 | 何をする画面か |
|---|---|---|
| `/` | 案内画面（Web） | 困りごとから公式情報へ案内する。このアプリの本体 |
| `/status` | 運用ステータス（Web） | 緊急縮退中かどうかを確認する。**停止状態を知る唯一の経路** |
| `index` | ホーム（モバイル） | `/` のネイティブ版 |
| `offline-guides` | オフライン行動カード（モバイル） | 通信不可でも読める一般手順4種 |
| `about` | 安全と出典について（モバイル） | 収集しない情報・AIの役割・外部サイトの扱い |

**`/` の操作の流れ**:

1. 最上部に **119・110** が常時ある（緊急縮退中も消えない）
2. **困りごとグリッド**（緊急・安全／水・給水／食料・生活／避難所／薬・医療／連絡・充電／移動・道路／片付け・制度の8種）から選ぶ。または**地域から選ぶ図**と**キーワード**で絞り込む
3. 該当する**アクションカード**が一覧に出る（全20枚のうち条件に一致した分）
4. カードは上から順に、**出典から写した答え**（応急給水所の名称・住所、無料入浴23施設の営業時間と店休日など）→ 手順 → **公式ページで必ず確認する区別**（飲料用/生活用水など）→ **順番を間違えると取り返しがつかないこと**（片付け前に写真を撮る等）→ 公式サイトを開くリンク
5. 期限が切れたカードは概要が「現在の状況は確認できません」へ切り替わる。**手順は残り、場所・時間だけ消える**

文字サイズは標準/大/特大の3段階、ダークモード対応、キーボード操作とスクリーンリーダー向けラベルを備えます。オフライン時は外部リンクを無効化し、電話の導線だけ残します。

### 地域から選ぶ図について

市町村の絞り込みは、7つの地域を面で並べた図になっています。各タイルは「そこを名指しした案内が何件あるか」と「そのうち期限切れ・未確認が何件か」を出します。

**これは地図ではありません。** 位置関係は実際の地理と異なり、点（ピン）も置きません。施設名から緯度経度を引くことは出典に書かれていない情報を推測で作ることであり、地図上のピンは「そこが今使える」と読ませてしまうためです。地図ライブラリもタイル画像も座標データも持たないので、実行時に外部へ出ていく通信はこの機能でも0のままです。

出している件数は**公式ページで確認できた案内の数**であって、現地が今使えるかどうかではありません。この図の狙いは件数の多さを見せることではなく、**固有の案内が0件の地域を0件のまま見せること**にあります（2026-08-02 時点では宇土市）。従来の `<select>` では、宇土市を選んでも県全域の案内が並ぶため、その地域の情報を持っていないことが利用者に伝わりませんでした。

決定と却下した案（ピン地図・外部タイル・実形状ポリゴン）は **[docs/adr/0002-area-map-uses-municipality-tiles-not-pins.md](docs/adr/0002-area-map-uses-municipality-tiles-not-pins.md)**。

ワイヤーフレーム・状態遷移図・カード内の全要素は **[docs/design/screens.md](docs/design/screens.md)**。

## 期限と受付時間

カードは**2つの独立した時間軸**を持ちます。混同するとどちらの守り方も壊れます。

| 軸 | 意味 | フィールド |
|---|---|---|
| **期限** | この情報を**信じてよいか** | `expiresAt` |
| **受付時間** | 行けば**受け取れるか** | `availableWindows`（当日限りの2枚のみ） |

### いつ期限切れになるか

| | |
|---|---|
| 既定 | `checkedAt` から**24時間**。`patrolled()` ヘルパーが `PATROL_EXPIRES_AT` を全カードへ配ります |
| 例外（当日限りの告知2枚） | 当日の**最終受付の終了時刻**。応急給水 `water-station` は19:00、氷川町の配布 `food-hikawa` は17:00 |
| 判定 | `now >= expiresAt`（`isExpired()`）。**境界ちょうどで期限切れ**＝安全側へ倒します |
| 時計 | **端末のローカル時計**。60秒ごとに再判定するのでリロード不要です。サーバー側の緊急停止スイッチとは無関係に動きます |

### 期限切れになると何が変わるか

| 消える | 残る |
|---|---|
| 概要（`summary`）→「現在の状況は確認できません」へ差し替え | 手順（`steps`）、確認すべき区別（`verifyPoints`）、取り返しがつかない順序（`irreversibleOrder`）、公式リンク |
| その日限りの答え（`facts` の `dated: true`）＝給水所の一覧・配布時間 | 日付に依存しない答え（`dated` なし）＝問い合わせ先など |

つまり **「何をすればよいか」は残り、「どこで・何時に」だけが消えます**（`visibleFacts()`）。カードに「期限切れ」バッジが付き、画面上部の鮮度バーが件数に応じて fresh / mixed / stale へ変わります。

### 期限内でも受け取れない時間がある

期限だけでは無駄足を防げません。氷川町の配布は9:00〜11:00と15:00〜17:00の2回で `expiresAt` は17:00なので、**間の11:00〜15:00は誰もいないのにカードは「有効」**でした。これを塞ぐのが `availableWindows` です（`serviceWindow()` / `serviceWindowNotice()`、期限内のカードにだけ出ます）。

**断定してよい方向を非対称にしています。**

- **受付時間外は言い切る** —「いまは受付時間外です。次の回は…」。告知に書かれた時刻からの帰結なので確実です
- **受付時間内は言い切らない** —「**告知では**受付時間内です（…、あと約1時間30分）。中止・早期終了があるため、出発前に…」。緑を成功色に使わないのも同じ理由です

`expiresAt` と `availableWindows` は毎日の巡回で**両方**を当日分へ書き換えます。片方だけ直すと `npm test` が落ちます（最終枠の終了＝`expiresAt`、全枠が `checkedAt` と同日）。

### 期限切れの表示は異常ではありません

巡回が1日途切れれば20枚すべてが同時に期限切れへ落ちます。これは劣化ではなく設計で、古い情報が新しい顔で出続けるより安全側です。**公式ページを再確認せずに `expiresAt` を延ばすことは鮮度の捏造**にあたり、このアプリが唯一守ると約束した品質基準に反します。

未解決の既知問題として、巡回時刻（11:25）が応急給水の開始（8:00）より遅いため、**8:00〜11:25は給水中でも前日データが失効して「期限切れ」表示**になります。実装では解決せず、巡回時刻を早めるしかありません。

時刻4種と `availableWindows` の制約は **[docs/design/data-model.md](docs/design/data-model.md)**、カード内の出し分けは **[docs/design/screens.md](docs/design/screens.md)**、巡回の判定ルールは **[docs/OPERATIONS.md](docs/OPERATIONS.md)** です。

## 開発の勘所

最初に押さえておくと事故らない4点です。

**1. カード内容の正典は `lib/disaster-data.ts` の1か所だけ。** モバイル版の `apps/mobile/src/data/actions.ts` は自動生成物なので直接編集しません。正典を編集したら必ず再生成します。

```bash
npm run gen:mobile-data
```

再生成を忘れると `npm test` が落ちます（`tests/mobile-parity.test.mjs`）。

**2. 各カードには鮮度の情報が必須。** `sourceName` / `sourceUrl` / `publishedAt` / `fetchedAt` / `checkedAt` / `expiresAt` / `sourceStatus`。期限切れと受付時間の扱いは上の「[期限と受付時間](#期限と受付時間)」にまとめてあります。公式ページへの接続確認だけで、掲載内容の現在性を保証してはいけません。

**3. 誤案内は実行時の環境変数で止められる。再ビルド・再デプロイは不要。**

```bash
npx wrangler secret put EMERGENCY_MODE     # 値は true
npx wrangler secret delete EMERGENCY_MODE  # 解除
```

`/status` が「緊急縮退中」になれば効いています。ローカル確認は `EMERGENCY_MODE=true npm run start`（Node）または `.dev.vars` に書いて `npm run dev`（workerd）。`vinext dev` はシェルの環境変数を読みません。

**4. 環境変数名に `NEXT_PUBLIC_` を付けてはいけません。** vinext は `NEXT_PUBLIC_*` を rsc / ssr を含む全環境へ define するため、値がサーバー側へ定数として焼き付き、**以後どの環境変数を変えても停止できなくなります**。過去に実際に踏んだ事故です（`docs/FIXES.md`）。

停止が届く範囲（開いたままのタブ・オフライン利用者・ネイティブには届きません）、重大度の分類、訂正手順は **[docs/OPERATIONS.md](docs/OPERATIONS.md)**。

## 公開状態と残課題

現在の判定は **`implementation_complete_boundary_unverified`** です。コードとローカル検査は通っていますが、実配信・実機・現地運用の証拠がありません。

R1（Web先行公開）に残るブロッカーは、**本番 Workers での停止スイッチ実操作**、**問い合わせ窓口 URL の確定**、**本番URLでの配信確認**の3つです。R2（ストア申請）は実機・支援技術の検証と、ネイティブに停止経路が無いことの受諾が前提になります。

公開前に残る課題（No-Go）の全体、Acceptance Chain、日付別の検証実測ログ、リリース手順は **[docs/RELEASE_AUDIT.md](docs/RELEASE_AUDIT.md)**。

**公開後もずっと続く前提**として、24時間期限のため**毎日1回の再確認巡回が必須**です。巡回が止まれば全カードが期限切れ表示へ縮退します（古い情報を新しいものとして出し続けることはありません）。
